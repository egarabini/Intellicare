## Decisões técnicas

**Florence usa Marie com fallback gracioso.** `suggest_soap()` tenta `call_marie("florence_soap_rag", ...)` primeiro. Se Marie falhar (timeout, 5xx, provider_not_initialize), cai no LLM local com `get_active_prompt()`. Zero impacto para o usuário final.

**Circular import resolvido preventivamente.** `_get_florence_timeline_context()` criado em `shared/timeline_context.py` em vez de `cuidado/services.py` — evita ciclo `florence ↔ cuidado`.

**Fernet para certificados.** `SERVER_ENCRYPTION_KEY` via env — rotação da chave inutiliza todos os certificados armazenados. Documentado explicitamente no `.env.example`. Chave gerada e registrada em local seguro antes do deploy de staging.

**KPI endpoint role fix.** `require_role("GESTOR")` → `require_role("TENANT_GESTOR")` em `router.py:512` — descoberto no Bloco 3 do staging sync, corrigido antes do fechamento.

**Query defensiva em journeys.** `kpis.py` verifica `information_schema` antes de consultar `journeys` — tenants sem a migration retornam 0 em vez de 500.

## Gotchas confirmados em produção

| Gotcha | Como se manifestou | Resolução |
|--------|-------------------|-----------|
| `pyhanko` exige PDF finalizado | N/A — implementado corretamente | `sign_pdf()` chamado após `render_pdf()` retornar |
| Dify 0.6.11 não usa `DATABASE_URL` | Container `marie-api` não subia no staging | Variáveis individuais: `DB_HOST`, `DB_PORT`, etc. |
| Volume DB com credenciais antigas | `marie-db` rejeitava conexões | Remover volume + recriar container |
| `MARIE_API_KEY` não propagada | `call_marie()` retornava 401 | `dify_setup.py` automatiza criação de conta, app e key |
| `setup_keycloak.py` inutilizável | Hang em `clinico-dev` | Admin REST API do Keycloak via curl |
| Commits locais nunca empurrados | DEM-080/081 ausentes em `origin/main` | Cherry-pick via `.tmp_push_fix` worktree limpo |
| Role `GESTOR` vs `TENANT_GESTOR` | KPI endpoint retornava 403 | Fix em `router.py:512` |
